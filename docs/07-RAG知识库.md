# 数字人 RAG：本地非遗知识库

> 相关文档：[03-穿越系统](03-穿越系统.md) · [04-语音与数字人](04-语音与数字人.md) ·
> [05-开发与校验](05-开发与校验.md)

数字人的回答现在会先检索项目根目录的 **`asset/` 非遗资料库**，把命中的项目卡、正文段落与传承人资料
拼进系统提示，并在回答里用 `[1][2]` 标注引用；前端同时显示「参考资料：1.《…》 2.《…》」。
整套检索在本地完成，不依赖向量服务，**离线可用**。

---

## 一、资料库是什么

`asset/` 是清洗后的结构化非遗数据，按 **头 / 腰 / 尾** 三层组织（详见 `asset/README.md`）：

| 层 | 含义 | 项目 | 正文段落 | 传承人 |
| --- | --- | --- | --- | --- |
| head | UNESCO 名录项 | 101 | 241 段 | 503 条 |
| waist | 其余国家级名录 | 3,512 | 9,890 段 | 6,545 条 |
| tail | 31 省省级代表性项目 | 16,832 | 773 段（河南） | 22,361 条 |

另有约 **21 万条三元组**（门类 / 级别 / 批次 / 年份 / 申报地区 / 代表性传承人），
构建索引时按实体合并进项目卡与传承人卡，不单独占检索条目。

---

## 二、索引结构

`python tools/build_rag_index.py` 会生成 `data/rag/ich.db`（不进 git）：

```
chunks        60,758 块：project 20,445 / passage 10,904 / inheritor 29,409
chunks_fts    FTS5(trigram) 全文索引（title + text）
titles        47,335 个实体标题
titles_fts    FTS5 标题 bigram 索引（中文两字词也能命中）
rag_meta      构建时间、asset 签名、统计
```

- 正文段落逐段切块（每块 ≤1200 字），前缀带「《标题》（门类，地区）」；
- 项目卡把「门类 / 编号 / 批次 / 年份 / 申报地区 / 保护单位 / 三元组事实」合成一张卡；
- 传承人卡带「姓名 / 性别 / 民族 / 生年 / 项目 / 批次 / 地区 / 简介」，简介过长再分段；
- **asset 签名**（文件数 + 总字节 + 最新 mtime）存进 `rag_meta`，资料改动后索引会自动标记过期。

本机实测：**3.0 秒**建完 60,758 块，索引 **99.7 MB**。

## 三、构建与状态

```bash
python tools/build_rag_index.py            # 构建/增量判断（asset 没变会直接跳过）
python tools/build_rag_index.py --force    # 强制重建
python tools/build_rag_index.py --status   # 只打印状态
```

服务启动时（`main.py` lifespan）会调用 `rag.warmup()`：索引缺失或过期就在**后台线程**重建，不阻塞启动；
构建期间检索返回空，回答照常进行（只是没有参考资料）。

配置（`.env`，均有默认值）：

```ini
RAG_ENABLED=true
RAG_TOP_K=6                 # 城市对话取几块；朝代对话固定取 4 块
RAG_ASSET_DIR=./asset
RAG_DIR=./data/rag
```

## 四、检索策略

纯本地、无 embedding，针对中文做了三层兜底：

1. **完整标题匹配**：先看提问里是否直接包含某个实体标题（如「苗族古歌」），命中给最高权重；
2. **标题 bigram 索引**：`titles_fts` 把标题拆成两字词，「剪纸」「昆曲」「藏戏」这类两字查询也能命中；
3. **正文 trigram 全文检索** + **两字词 LIKE 兜底**：长问句去掉「请问 / 介绍 / 什么 / 的」等停用词后切词检索。

排序时叠加：

- 类型权重：项目卡 > 正文段 > 传承人；问「传承人/谁」时传承人加权；
- 门类 / 省份识别：「贵州有哪些传统舞蹈」会自动给「传统舞蹈 + 贵州」的条目加权；
- 同一实体最多 1 张项目卡 + 2 段正文 + 1 位传承人，保证回答既有档案事实、也有故事内容。

接口（也可直接调试）：

```bash
curl http://127.0.0.1:8000/api/rag/status
curl -X POST http://127.0.0.1:8000/api/rag/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"苗族古歌讲的是什么","top_k":5}'
curl -X POST http://127.0.0.1:8000/api/rag/rebuild -H 'X-Admin-Token: dev-token'
```

## 五、对话接入

- **城市讲解 / 规划面板**：`/api/chat` 在原文回答前先检索（查询 = 城市名 + 问题），命中结果带编号拼进
  system prompt；SSE 先发 `sources` 事件，再流式输出 `token / sentence / human`。
- **穿越模式**：`/api/dynasty/{key}/chat` 的查询 = 时期 + 当前地点/诗词 + 问题，取前 4 块，
  同样走数字人原有链路，只是提示词多了「本地资料库检索结果」一段。
- **引用**：提示词要求「优先采用检索结果，引用时在句末标 [1][2]，不要编造资料里没有的年份、数字或人名」。
- **无 Key 时**：Mock 模式会直接朗读第一条检索资料（截断到 220 字）并注明「据本地非遗资料库」，
  不再只答「资料有限」。
- **前端**：`voice.js` 解析 `sources` 事件 → `main.js` 分发 → 城市面板 / 规划小面板 / 穿越卡片各追加一行
  「参考资料：1.《…》 2.《…》」，鼠标悬停可看层级、门类与地区。

截图产物：`tests_artifacts/30_rag_sources.png`。

> 说明：这是**词法检索 RAG**（标题 + 全文 + 停用词/门类/省份加权），不是向量检索。
> 对本资料库这种「大量专名 + 结构化事实」的场景，词法检索的命中率与可解释性更好、无需 GPU 或外部额度；
> 若以后要接 bge-m3 之类的向量检索，可在 `search()` 后做 RRF 融合，索引仍以 SQLite 为准。
