# 千年 · 开场 · 旅行电影（第一批叙事改造）

> 相关文档：[01-沙盘与日照](01-沙盘与日照.md) · [02-行程规划与攻略](02-行程规划与攻略.md) ·
> [03-穿越系统](03-穿越系统.md) · [04-语音与数字人](04-语音与数字人.md) · [05-开发与校验](05-开发与校验.md)

这一批改造把「六个并列模块」串成一条能看完的动线：**开场 30 秒 → 沙盘 → 一块土地的千年 →
排行程 → 导出旅行电影**。三件事都建立在既有资产上，不推倒重来。

---

## 一、开场：你和这片土地的故事（A1）

每次打开都会播（约 22 秒），2 秒后出现「跳过」；导航抽屉里有「重播开场」；
`?intro=0` 直接进沙盘（自动化测试用）。

五段运镜（`frontend/js/intro.js` + `frontend/js/camera_track.js`）：

1. **太空俯冲**：相机沿关键帧曲线从高空收拢，标题「你和这片土地的故事」浮起；
2. **穿云**：幕布水汽起落（复用晕影与幕布，不新建体积云）；
3. **晨昏线扫过**：舞台时间从 04:50 加速到 19:10（北京时间），日照 shader 真的扫出晨昏线；
4. **城市次第点亮**：城市光点按经度从西到东亮起（`citypoints` 的 `setReveal`）；
5. **定格与开场白**：镜头停在上次访问的城市（`localStorage.cl.lastCity`），否则西安；
   数字人用一句开场白收尾，随后回到实时日照。

## 二、一块土地的千年（A2，城市卡新入口）

穿越全景是「按朝代看全图」；**千年模式反过来**：锁定一个城市点，让时间在这个点上流动。

### 怎么进

沙盘上单击任意城市 → 城市卡 / 城市面板上的**「千年 / 一块土地的千年」**。
有 ≥2 期记载的城市都能进，十座精选城市（西安、洛阳、北京、南京、成都、杭州、苏州、敦煌、泉州、开封）
保证 11 期全部有内容；记载太少的城市会提示换一座。

### 界面上有什么

- **底部时间轴**：秦 → 现代 11 格，每格写着当期古名（内史 → 长安 → 大兴城 → 京兆府 → 奉元路 → 西安…）；
  ◀ / ▶ 或直接点格子拖动时间；切换时疆域「淡出 → 重建 → 淡入」，镜头始终锁在这一个经纬度上；
- **锁定点名牌 + 近旁地名**：30km 内的历史地名以小名牌补位，点开看当期讲解；
- **诗词光字**：写作地落在这附近的诗词会以光字浮起（复用穿越模式同一套渲染）；
- **历史地层**：右侧抽屉一期一层（年代 / 古名 / 一句话），点击直接跳期；
- **日照随朝代**：每期有一个代表时刻（唐·夏至黄昏、元·冬至上午、清·中秋夜……），现代一期回到实时；
- **与当朝人说话**：卡片里可以直接提问，服务端把「锁定点 + 当期古名 + 当朝人设」写进提示词，
  模型用当朝人的口吻回答（唐称「郎君」、元自称「俺」），且只知本朝之事。

### 数据怎么来

后端 `backend/app/data/millennium.py`：**不改动既有朝代数据**，只做聚合与策展。

```
GET /api/dynasty/millennium?name=西安&lng=108.94&lat=34.34
→ { counts: {matched, total}, featured, eras: [ {key, name, period, color, lighting, persona,
     matched, source, place{ancient,modern,kind_label,summary,narration…}, poems, note} ] }
```

逐期匹配顺序：**今名精确 → 今名前缀（西安 → 西安阎良）→ 策展补注 → 60km 内最近地名**。
`source` 会如实标注来源（exact / prefix / near / curated），空档给出「此朝疆域未及此地」或
「此朝此地暂无记载」。

- 每个朝代在 `dynasties.py` 的 `MILLENNIUM_META` 里各有一条**当朝人设**与**代表时刻**；
- 十座精选城市的断档与跨城说明写在 `millennium.py` 的 `CURATED`；
- 属于本市域的缺格（宋·京兆府、明·西安府、元·河南府路……）以次级地名补进对应 `dynasty_*.py`，
  顺带让穿越全景的地图更完整；
- 对话接口新增可选 `anchor`（锁定点说明），与城市对话、朝代对话共用同一条 SSE/TTS/口型链路。

## 三、旅行电影（A3 轻量版）

入口：**我的攻略 → 导出旅行电影**。把整份攻略渲染成一段 30–60 秒的 WebM：

1. **脚本编译**（`buildMovieScript`，纯函数）：按天生成日卡、点位字幕与旁白文案（模板生成，不走大模型），
   总时长超过 72 秒会按比例压缩；
2. **沙盘拍摄**：相机按天飞过攻略里的城市，地标升起（带尘土粒子），
   每到一个城市把舞台时间切到当天第一站的时刻——晨昏线随行程扫过；
3. **合成与录制**：叠加画布逐帧合成「沙盘画面 + 电影黑边 + 日卡 + 字幕 + 封尾卡（行程概览 + 分享二维码）」，
   `captureStream(30)` 与 WebAudio 混音流一起交给 `MediaRecorder(vp9/vp8, opus)`；
4. **声音**：TTS 旁白逐句解码后按时间轴调度；配乐优先用 `frontend/assets/audio/guqin.*`，
   没有素材时用程序化古琴（Karplus-Strong 拨弦合成）；
5. **封尾二维码**：`GET /api/guides/{id}/share-qr.png`（首次导出会自动生成只读分享 token）。

导出是**实时录制**（约等于脚本时长），完成后可以页内回看与下载；
浏览器不支持 `MediaRecorder / captureStream` 时会明确提示改用 Chrome / Edge。

> 想发朋友圈：下载 WebM 后用任意工具转 MP4 即可；后续要接 `ffmpeg` 只需在后端加一个转码接口，
> 前端已经拿到可复用的 Blob。

## 四、皮相（P0 / P1）

- **字体**：标题与卡片统一走衬线字体栈（优先系统里的 `Noto Serif CJK SC`，OFL 许可），正文保持无衬线；
- **配色**：新增石青 `--stone`、朱砂 `--cinnabar`、赭石 `--ochre` 三个矿物色变量，
  千年时间轴、地层、电影进度条都取这些颜色；
- **转场**：卡片出现用水墨晕染（`inkReveal`）；换期用一层水汽 veil；
- **微交互**：地标升起保留回弹曲线，并加了一圈升腾的尘土粒子；城市光点呼吸幅度增强；
- **环境音**：导航抽屉里可调音量，静音按钮统一控制；数字人播报时环境音自动压低（ducking）；
  风声 / 水声为 WebAudio 合成，古琴为程序化拨弦，**不依赖任何第三方音频素材**。

素材通道：把 CC0 音频放进 `frontend/assets/audio/`（`wind` / `water` / `guqin` 三个名字，
支持 webm / ogg / mp3），环境音与电影配乐会自动优先使用它们。
