# 像素造境 · 设计稿

日期：2026-11-18  
状态：待确认  
范围：洛阳「入画」入口 + 全局「像素造境」功能 + 主界面视觉整理

---

## 1. 意图与为什么

龙门石窟像素 demo 已经完成并接入 `frontend/demo/longmen_park.html`，效果得到认可。接下来希望：

1. 把龙门 demo 变成洛阳这座城市的真实入口：用户在地图上打开洛阳时，出现一个「进入像素龙门」的画面。
2. 把「按一句话生成文旅像素场景」做成项目的全局特色功能：用户输入一句话，系统联网检索地方资料，调用像素美术 Skill 的规则，生成一张可导出的高清像素场景图。
3. 为以后每个省会做自己的「像洛阳一样的游戏」留出可复用的场景原型与素材生成能力；首版只做图片，不做每个城市的可玩场景。
4. 在生成过程中让用户看到「正在加载 Skill」「正在检索资料」「正在绘制」等真实进度，而不是一个无反馈的转圈。
5. 顺手整理主界面按钮、面板和视觉层级，让新功能与现有「宣纸 + 墨 + 赭金 + 印章红」的语言一致。

选择「一张图」而不是「可玩场景」的原因：图片生成链路更短、更可控，也更容易扩展到不同建筑；可玩场景需要逐城市做交互、碰撞、剧情与素材校验，当前阶段太重。

## 3. 目标 / 非目标 / 反目标

### 目标

- 打开洛阳时，出现一次「入画」画面，并可从洛阳面板重复进入龙门 demo。
- 主界面有一个全局「造境」入口，打开「造境画室」。
- 用户用一句中文描述，生成一张 16:9 像素场景图；不要求用户上传图片。
- 生成过程展示真实的工具进度：检索资料、加载 Skill、设计画面、绘制、校验。
- 结果可预览、可下载：场景图、明信片版、打包 zip。
- 生成失败时有可理解的降级路径（无模型、搜索失败、渲染失败）。
- 首版至少能稳定表现：山崖石窟、古塔、城门/宫殿、水乡/拱桥、山岳、现代天际线六类场景。
- 不破坏现有地图、城市面板、Live2D、数字人、规划/攻略等功能。

### 非目标

- 不做每个省会的可玩游戏；只保留场景原型和数据结构，方便以后扩展。
- 不接外部付费生图模型作为首版必需依赖；以后可以作为可选后端。
- 不做用户上传参考图、像素级编辑、多人画廊、分享社区。
- 不重做整个地图视觉，只做与本次功能相关的按钮、面板、浮层与响应式整理。

### 反目标

- 不能生成「看起来像像素风」的普通 AI 图后直接交付；色板、尺寸、alpha、像素边缘必须可校验。
- 不能为了出图而绕过 Skill 的色板与尺寸约束。
- 不能让生成过程黑箱化；用户必须看到每一步在做什么。
- 不能因为新功能让主界面多出一堆互不相干的悬浮按钮。

## 4. 方案选择

### 生成引擎

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 程序化像素渲染 + LLM 场景 JSON | LLM 解析意图并输出受控 JSON，Pillow 按 InkGongbi48 绘制 | 可控、快、无需图像 API、像素规则稳定、可复用到以后的城市游戏 | 需要积累场景原型，丰富度有限 | **采用** |
| B. 外部 AI 生图 + 像素后处理 | 生成大图，再降采样、量化、清理 | 任意建筑都能画、视觉丰富 | 需要新 Key/费用，像素风不稳定，文字与结构易崩，版权与可控性差 | 以后可选 |
| C. LLM 现场写绘图脚本 | 每次让模型写 Python 并在沙箱执行 | 灵活 | 慢、不可控、安全与稳定性风险 | 不采用 |

### 搜索

- 首版使用无需 Key 的 **中文维基百科 + Wikimedia Commons** 搜索接口，获取地点摘要、关键事实、参考图标题与许可信息。
- 结果缓存到 `data/atelier/cache/search/`（24 小时）。
- 未来可通过环境变量接入 Tavily/Serper 等付费搜索；接口设计保持 provider 可替换。
- 搜索结果只作为事实提示，不直接作为指令；最终仍由受控的场景 JSON 和渲染器决定输出。

### 体验入口

- 全球入口放在主界面左上角，与「导航」并排成一对印章按钮：「导航」「造境」。
- 「造境」打开全屏「造境画室」浮层，而不是右侧抽屉：画室需要输入、进度、预览、导出四块空间，全屏更能承载，也不会与 Live2D、城市面板互相遮挡。
- 洛阳入口采用「城市面板入画卡 + 一次入画浮层」：面板卡常驻，浮层只在用户主动打开洛阳时出现一次（每个浏览器会话一次），不打断开场。当前代码不会在开场后自动打开城市面板（`cl.lastCity` 只用于确定开场镜头终点），所以只需处理显式打开洛阳的情况。

## 5. 用户体验

### 5.1 洛阳「入画」

**触发**

- 用户在地图上主动打开洛阳（单击标签/光点/搜索后进入 `openCity('luoyang')`）时：
  1. 左侧城市面板顶部出现「像素龙门」入画卡（常驻，可重复点击）。
  2. 如果本会话还没看过入画浮层，则在城市面板出现后约 600ms 弹出「入画」浮层。
- 当前代码不会在开场后自动打开城市面板（`cl.lastCity` 只用于确定开场镜头终点）；入画浮层只在用户显式打开洛阳时出现。若以后加入自动恢复城市面板，需要传入 `silent` 标记来抑制浮层，只保留面板卡。
- 其他城市不出现入画卡。

**入画卡**

- 位置：城市面板头部下方、简介上方。
- 内容：龙门像素场景缩略图、`PIXEL LUOYANG` 小标、标题「龙门石窟 · 伊水公园」、一句短描述、按钮「进入像素龙门」。
- 缩略图使用 `frontend/demo/assets-v2/backgrounds/bg_fengxian_niche.png` 或堤岸图做 CSS 裁切，不新增像素素材。
- 视觉：与城市面板一致，用印章红做小标，金色发丝描边。

**入画浮层**

```text
┌────────────────── 入 画 ──────────────────┐
│        [ 龙门石窟像素场景预览 ]            │
│  PIXEL LUOYANG                            │
│  龙门石窟 · 伊水公园                      │
│  沿伊水东岸走一趟，把五处景点盖成朱砂印。 │
│  [进入像素龙门]   [留在沙盘]              │
└───────────────────────────────────────────┘
```

- 全屏半透明墨色幕布，中央一张宣纸质感卡片，16:9 预览图 + 标题 + 描述 + 两个按钮：「进入像素龙门」「留在沙盘」。
- 右上角关闭；底部有一行小字「本会话不再自动提示」，可勾选。
- 点击「进入像素龙门」：打开全屏 demo 浮层，而不是让用户丢失当前地图视角。

**demo 浮层**

- 顶部一条细工具栏：「龙门石窟 · 伊水公园」+「返回沙盘」+「新窗口打开」。
- 内容区是 `iframe src="/demo/longmen_park.html"`，占满剩余视口；关闭时把 iframe 的 `src` 置空，停止游戏循环。
- 背景层不再渲染地图交互；Esc 关闭。
- iframe 的键盘事件归 demo 所有；主页面在浮层打开期间不监听移动键。
- 移动端同样使用 `100dvh`，demo 自身的 `fit()` 负责缩放。

### 5.2 造境画室

**布局草图**

```text
┌─ 像素造境 ──────────────────────────────────────────────[×]─┐
│ ┌─ 左栏 380px ─────────┐  ┌─ 右侧预览 ───────────────────┐ │
│ │ 一句话，画一幅…       │  │                              │ │
│ │ ┌──────────────────┐ │  │       16:9 场景预览           │ │
│ │ │ 洛阳龙门石窟，黄昏…│ │  │                              │ │
│ │ └──────────────────┘ │  │  龙门石窟 · 伊水公园          │ │
│ │ [生成]  [示例 chip]   │  │  1920×1080 · InkGongbi48     │ │
│ │ ✓ 理解描述            │  │  [场景图] [明信片] [zip]     │ │
│ │ ✓ 检索资料 · 维基     │  └──────────────────────────────┘ │
│ │ ◐ 加载 Skill …        │                                   │
│ │ ○ 设计画面            │                                   │
│ │ ○ 绘制场景            │                                   │
│ │ ○ 逐像素校验          │                                   │
│ └──────────────────────┘                                   │
└────────────────────────────────────────────────────────────┘
```

**入口**

- 左上角「导航 / 造境」一对按钮，保持现有印章风格；「造境」用金色描边和一个小朱砂点区分。
- 打开后全屏浮层，Esc/关闭按钮返回沙盘。
- 同时把「造境」加入导航抽屉的「工具」区，方便已打开抽屉的用户找到。

**布局**

- 桌面：最大 1240×820，左侧 380px 控制栏，右侧预览区。
- 左侧从上到下：
  1. 标题「像素造境」+ 副标题「一句话，画一幅你的文旅像素场景」。
  2. 文本输入（最多 200 字），占位示例「洛阳龙门石窟，黄昏，伊水与崖壁大佛」。
  3. 4 个示例 chip，点击填入输入框。
  4. 「生成」主按钮，生成中变为「正在造境…」并禁用。
  5. 进度时间线：理解描述 / 检索资料 / 加载 Skill / 设计画面 / 绘制场景 / 逐像素校验。
  6. 对话式反馈：时间线上方显示一行助手的短句，例如「好，画一幅『洛阳 · 龙门石窟』的黄昏场景」，让用户感到是在和 agent 对话，而不是提交表单。
  7. 资料来源小列表（折叠，最多 3 条，带外链）。
- 右侧：
  1. 16:9 预览框，纸边框 + 金色发丝线。
  2. 未生成：淡墨底 + 印章水印 + 「写下你想去的地方」。
  3. 生成中：当前步骤的墨迹 loading + 已完成的进度。
  4. 完成：场景图淡入，图下方显示标题/副标题/色板/尺寸，以及「下载场景图」「下载明信片」「下载 zip」「再画一张」。
  5. 「再画一张」保留原描述，换随机种子重绘；可选「润色」输入追加一句（如「再加一场雪」），提交后沿用同一地点与场景类型，只改变天气/时辰/构图，形成轻量对话式迭代。
- 移动端：单列，预览在上、控制在下的顺序可读；画室可滚动。

**进度反馈**

- 每个步骤有 pending / active / done / error 四态。
- active 步骤显示动态点与当前细节，例如：
  - 「正在加载像素 Skill」→「InkGongbi48 · 48 色 · 960×540」
  - 「正在检索地方资料」→「维基百科 · 龙门石窟」
  - 「正在设计画面」→「崖壁大佛 + 伊水 + 黄昏薄雾」
  - 「正在绘制场景」→「天空 → 远山 → 崖壁 → 水面 → 前景」
- 步骤事件来自后端 SSE，不是前端假动画。

### 5.3 生成与导出

- 服务端生成 960×540 逻辑像素场景；导出时用最近邻 2× 放大为 1920×1080，保证像素块清晰。
- 明信片版 2112×1432：内嵌 **2× 场景 1920×1080**（不做 1.8× 或非整数缩放），四周 96px 纸边框，底部 160px 题签区，绘制标题/副标题/日期/朱砂印章。优先使用系统 Noto Serif CJK；字体缺失时退化为无字边框，并在 UI 里补标题。
- 明信片是展示层，**不受** InkGongbi48 / alpha 0/255 校验约束；文字与纸边框允许正常的字体渲染。像素色板与 alpha 验收只作用于 `scene.png` 和 `scene@2x.png`。
- zip 内容：
  - `scene.png`（960×540）
  - `scene@2x.png`（1920×1080）
  - `postcard.png`（2112×1432，内嵌 2× 场景）
  - `scene.json`（完整场景 spec、搜索来源、提示词、时间、色板）
  - `README.txt`（生成方式、色板、素材与参考来源说明）
- 文件保存在 `data/atelier/<job_id>/`，通过受控路由下载；保留最近 50 个任务，超出后清理最旧的。

## 6. 风格与六项确认（pixel-asset-master Step 3/4）

本功能会生成像素画面，按项目 CLAUDE.md 必须先完成风格确认与六项确认。以下是本功能的风格契约；**用户确认本设计稿即视为对本次功能 Step 3 与 Step 4 的明确确认**。确认后渲染器才能进入实现。若以后新增场景原型、改变画布尺寸或色板，需要重新确认增量项。

### Step 3：风格确认

- 风格：**Dense Detail + 选择性描边**，水墨工笔像素。
- 光向：左上暖光；轮廓用墨色，不用整圈黑边。
- 过渡：2×2/3×3 有意色块 + 选择性 Bayer 抖动；禁止椒盐噪点、抗锯齿、渐变、亚像素。

### Step 4：六项确认

| # | 确认项 | 本功能取值 |
| --- | --- | --- |
| 1 | 画布尺寸 | 逻辑 960×540；地标模块以 64×64 为基准；导出最近邻 2× 1920×1080 |
| 2 | 素材数量 | 首版 6 类地标模块（崖壁大佛、古塔、城门/宫殿、水乡、山寺、现代天际线）+ 共享天空/地形/水面/前景模块；6 张示例场景；无角色精灵 |
| 3 | 目标平台 | Web：FastAPI + Pillow 服务端渲染，PNG 导出；前端 Canvas/HTML 预览 |
| 4 | 色板 | InkGongbi48（48 色，来自龙门 `spec_lock.md`）；单图使用其子集，绝不引入色板外颜色 |
| 5 | 美术风格 | Dense Detail + 选择性描边；3 色阶明暗；2×2/3×3 色块；无抗锯齿 |
| 6 | 动画需求 | 首版无角色/场景逐帧动画，只出静态场景图；生成进度与墨迹淡入属于 UI 动画，不新增精灵帧 |

> 说明：Step 4 的第 6 项通常用于角色动作；本功能首版是静态场景，明确为「无角色动画」，后续做可玩场景时再单独确认动作表。

### 7.2 API

**POST `/api/atelier/stream`**

请求：

```json
{
  "prompt": "洛阳龙门石窟，黄昏，伊水与崖壁大佛",
  "seed": 123456,
  "session_id": "optional"
}
```

响应：`text/event-stream`。事件：

```text
event: stage
data: {"key":"intent","status":"active","label":"正在理解你的描述","detail":"洛阳 · 龙门石窟"}

event: stage
```

### 7.3 场景协议（SceneSpec）

```json
{
  "title": "洛阳 · 龙门石窟",
  "subtitle": "伊水东岸 · 黄昏",
  "place": "洛阳",
  "landmark": "龙门石窟",
  "landmark_type": "cliff_buddha",
  "environment": "river_valley",
  "time": "dusk",
  "weather": "mist",
  "season": "autumn",
  "palette": "InkGongbi48",
  "mood": "serene",
  "accent_role": "seal",
  "composition": {
    "horizon": 0.54,
    "landmark_x": 0.62,
    "landmark_scale": 1.0,
    "zoom": 1.0
  },
  "props": ["caves", "pines", "birds"],
  "caption": "伊水从两山之间穿过，崖壁上的佛龛在暮色里亮起。",
  "seed": 20261118,
  "created_at": "2026-11-18T12:00:00+08:00",
  "prompt": "洛阳龙门石窟，黄昏，伊水与崖壁大佛",
  "sources": [
    {
      "title": "龙门石窟",
      "url": "https://zh.wikipedia.org/wiki/龙门石窟",
      "publisher": "维基百科",
      "license": ""
    }
  ]
}
```

枚举（首版）：

- `landmark_type`: `cliff_buddha` / `pagoda` / `palace_gate` / `water_town` / `mountain_temple` / `skyline`
- `environment`: `river_valley` / `lake` / `canal` / `plain` / `coast` / `urban`
- `time`: `dawn` / `day` / `dusk` / `night`
- `weather`: `clear` / `mist` / `rain` / `snow`
- `season`: `spring` / `summer` / `autumn` / `winter`
- `props`: 从 `caves` / `pines` / `willows` / `birds` / `boat` / `lanterns` / `petals` / `snow` 中选
- `mood`: `serene` / `majestic` / `lonely` / `bustling` / `dreamy`；只作为渲染器的色阶与构图提示，默认 `serene`
- `accent_role`: `seal` / `gold` / `jade` / `stone` / `ochre`；渲染器从 InkGongbi48 解析成具体颜色，禁止 LLM 直接给任意 hex
- `seed`: 服务端生成或客户端传入；同一 scene spec + seed 必须产生同一张图
- `created_at` / `prompt`: 服务端写入，用于复现与 zip 清单；不参与 LLM 决策
- `sources[].license`: Wikimedia Commons 返回的许可文本；没有就留空。参考图不嵌入成图

未知值统一回退到 `cliff_buddha` / `river_valley` / `dusk` / `clear` / `autumn` / `serene` / `stone`，保证渲染器总能画出来。

### 7.4 生成流程与工具

1. **intent**：LLM 解析出地点、地标、场景类型、时间、天气、情绪；输出 JSON。无模型/调用失败时走规则解析：
   - 从 `cities` 表与 `LANDMARKS_CN` 匹配地名与地标；
   - 用关键词映射类型（石窟/大佛 → `cliff_buddha`，塔 → `pagoda`，城墙/门 → `palace_gate`，水乡/桥 → `water_town`，山/寺 → `mountain_temple`，高楼/夜景 → `skyline`）。
2. **search**：`web_search` 工具用中文维基搜索地点，取摘要与页面 URL；Wikimedia Commons 取相关图片标题/许可（仅记录，不嵌入）。失败时使用城市表与地标数据，并在事件里标注「使用站内资料」。
3. **skill**：`SkillLoader` 读取 `skill_bundle/SKILL.md` 与 `palettes/ink_gongbi48.json`，生成紧凑风格契约（色板、画布、描边、抖动规则），发给模型并发出 skill 事件。这是真实的读取，不是前端假步骤。
4. **plan**：LLM 在风格契约与搜索事实下输出 SceneSpec；Pydantic 校验；失败则用规则模板 + 默认值。
5. **render**：Pillow 在 960×540 上按图层绘制；每层完成后发 progress 事件；渲染是确定性的（seed 控制随机）。渲染是 CPU 同步任务，放到线程池执行（`asyncio.to_thread`），通过线程安全队列把 progress 回送到 SSE，避免阻塞事件循环。
6. **validate**：只检查 `scene.png` / `scene@2x.png` 的尺寸、色数、所有颜色都在 InkGongbi48、alpha 仅 0/255；失败则自动量化到色板后重试一次。`postcard.png` 是展示层，不参与色板/alpha 校验。
7. **export**：生成 2× 场景、明信片、zip、spec JSON；发 done 事件。

### 7.5 渲染器

- 逻辑画布 960×540；导出最近邻 2×（1920×1080）。
- 色板：InkGongbi48（48 色，沿用龙门 spec_lock 的 48 色）。渲染器只从该色板取色，不做渐变插值；需要过渡时用 2×2 Bayer 抖动或色阶。
- 图层顺序：
  1. 天空（时辰色阶 + 云带 + 日/月）
  2. 远山/地平线（低频起伏，不用规则正弦）
  3. 主地标（按 `landmark_type` 的模块）
  4. 中景环境（水面、堤岸、城墙、街巷）
  5. 前景（松/柳、石阶、栏杆、灯笼、船、人物剪影）
  6. 天气粒子（雾、雨、雪、花瓣、鸟）
  7. 暗角与纸面颗粒（低强度）
- 模块清单（首版）：
  - `cliff_buddha`：崖壁层理、佛龛群、主尊坐佛、背光、伊水/桥。
  - `pagoda`：3–9 层塔、塔刹、台基、树影。
  - `palace_gate`：红墙、城门、重檐/庑殿顶、灯笼、广场。
  - `water_town`：白墙黛瓦、河道、拱桥、乌篷船、柳树。
  - `mountain_temple`：层叠山峦、云雾、寺庙/塔、松林。
  - `skyline`：现代塔楼/桥、江面、灯光、车流光点。
- 复用规则：地标模块接收 `x`、`scale`、`accent_role`、`mood`、`seed`；环境模块接收地平线比例与水系类型。这样以后每个省会可以通过一个 preset 组合模块，而不是复制整套绘制代码。
- 明信片：2112×1432，96px 纸边框；内嵌 2× 场景 1920×1080；底部 160px 题签区绘制标题/副标题/日期/朱砂印。字体优先 `Noto Serif CJK SC`，找不到则退化为无字版。明信片不走 InkGongbi48/alpha 校验。

### 7.6 Skill 打包

- 新增 `backend/app/services/atelier/skill_bundle/`：
  - `SKILL.md`
  - `references/executor-pixel.md`
  - `palettes/ink_gongbi48.json`（从龙门 `spec_lock.md` 提取）
  - `scripts/asset_validator.py`（作为校验规则来源；运行时由 `validate_scene` 适配）
- 新增 `tools/sync_atelier_skill.py`：从 `.claude/skills/pixel-asset-master/` 同步到 bundle；bundle 随 `backend/` 进入 Docker 镜像。
- 不在运行时执行任意 Skill 脚本；Skill 负责提供规范、色板与校验规则。渲染器是 Skill 规范在应用内的受控实现。
- 依赖：`Pillow` 加入 `requirements.txt`；Docker runtime 安装 `fonts-noto-cjk`（明信片题签）。不引入 numpy。

### 7.7 搜索

- `backend/app/services/atelier/tools.py`：
  - `search_place(place, landmark)`：调用 `https://zh.wikipedia.org/w/api.php` 的 `list=search` 与 `prop=extracts`，取前 3 条摘要；再查 `commons.wikimedia.org/w/api.php` 取图片标题与许可。
  - 超时 4 秒；失败不阻塞生成。
  - 结果以 `SearchHit` 结构返回，写入 `scene.json` 的 `sources`。
  - 缓存键为规范化查询词，24 小时过期。
- 未来 provider 抽象：`search_web(query) -> list[SearchHit]`，默认 Wikipedia；可通过 `ATELIER_SEARCH_PROVIDER=tavily` 扩展。

### 7.8 存储与导出

- `DATA_DIR / "atelier" / <job_id>/`：
  - `scene.png`、`scene@2x.png`、`postcard.png`、`scene.json`、`scene.zip`
- 任务元数据写入 `data/atelier/index.jsonl`（时间、prompt、spec、文件路径），用于「最近造境」与清理。
- 保留策略：按创建时间保留最近 50 个任务；启动或每次生成后清理旧任务。
- `.gitignore` 增加 `data/atelier/`。

### 7.9 失败与降级

| 情况 | 行为 |
| --- | --- |
| 无 LLM Key / mock | 规则解析 + 默认 SceneSpec，仍完整出图；UI 标注「本地规则模式」 |
| LLM 输出非法 JSON | 自动修复一次；仍失败则规则模板 |
| 搜索超时/被阻断 | 使用站内城市/地标资料，事件标注「站内资料」 |
| 渲染失败 | 返回 error 事件；UI 保留输入与重试按钮 |
| 色板校验失败 | 自动量化到 InkGongbi48 后重试一次 |
| 下载文件不存在 | 404 + 可读提示，不暴露目录结构 |

### 7.10 安全与边界

- 搜索结果是外部不可信数据，只作为事实提示；不让其覆盖系统规则或输出任意代码。
- SceneSpec 使用 Pydantic 严格枚举；所有绘制参数有边界。
- 不执行 LLM 生成的代码；不 shell 调用。
- `job_id` 与文件名白名单校验；禁止路径穿越。
- 提示词最大 200 字；剥离控制字符；记录日志时截断。
- 生成接口不需要登录（本地演示），但做简单的每 IP 每分钟 6 次限流；超限返回可读错误。

## 9. 约束、风险与缓解

- **首版场景原型有限**：先做六类，优先洛阳/水乡/城门/古塔；以后按省会逐步加 preset，不改协议。
- **程序化画面不如手绘精细**：通过复用龙门模块、分层噪声、限制色板与固定构图来保证下限；首版以「一眼认出地标」为标准。
- **外部搜索不稳定**：缓存 + 站内资料降级；不让搜索失败阻断生成。
- **中文字体在容器缺失**：Docker 安装 `fonts-noto-cjk`；本地优先使用系统 Noto Serif CJK；找不到字体时明信片退化为无字版，UI 仍显示标题。
- **生成时间**：无模型/无搜索约 1–2 秒；含 LLM 与搜索约 5–10 秒。进度事件必须覆盖整个过程。
- **界面拥挤**：新增入口只加一个「造境」按钮；其他按钮做减法与对齐，不新增更多常驻浮层。
- **范围蔓延**：可玩场景、每省会游戏是后续工作，不在本设计内实现；数据结构为它们预留。
