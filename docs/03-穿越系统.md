穿越模式和行程规划是**两条互不干扰的路线**：穿越模式只看历史，不做流程编辑与优化；
退出后现代底图与全部图层原样恢复。

---

## 一、进入与退出

1. 打开「☰ 导航 → 穿越」，在下拉里选朝代（唐 618–907 / 宋 960–1279 / 明 1368–1644）；
2. 点「开始穿越」：沙盘浮雕底图**整体重建为该朝的示意疆域**（`outline` 闭合环），
   现代城市光点、地级市标注、省界省名、3D 地标全部收起；
3. 顶部出现**朝代状态条**（朝代 · 都城 · 年代 · 地名/诗词数量），随时点「返回现代」恢复全部现代图层。

从抽屉进「我的攻略 / 流程编辑 / 路线规划 / 抄作业」时会**自动先返回现代**，避免拿历史疆域去排现代点位。

## 二、地图上能看到什么

- **历史地名**（金色光点）：当时的地名（长安、洛阳、沙州、临安、应天府……）。鼠标悬停出名牌
  「长安（今 西安）」，点开卡片可看类型、简介、讲解词与内置问答。
- **诗词光点**（青色）：诗词写作地；同一地点多首诗绕成一个小环，点开是诗词卡——全文、背景、
  写作地今名，以及**「一说」存疑标注**（例：《静夜思》写作地一说扬州旅舍、一说安陆）。
- **光韵诗字**：每朝另有 **6 首代表诗词浮起两列竖排的「光字」**——每个汉字都是 canvas 画出的
  带光晕字形贴图，**加色混合叠在沙盘上，没有纸面或碑体背景**；笔画接近暖白、外圈是金色光晕，
  每个字独立朝向相机并轻微浮动呼吸。字串后有一层很淡的暗晕（白天保证可读）、一圈柔光与一道
  从地面升起的光柱；夜里整体更亮，悬停时整串字放亮放大。点光字或点光点都会打开对应的诗词卡。
- **昼夜随行**：底图重建后日照 uniforms 照常工作——把时间滑到夜里，该朝疆域一样会入夜，
  历史地名与诗词标记按各自所在地的昼夜独立亮灭。
- 抽屉里还有**「本朝诗词」列表**，点一首即飞到该诗的写作地并弹卡。

## 三、与数字人讨论（走大模型）

卡片底部输入问题即可：回答由**大模型流式给出**（`POST /api/dynasty/{key}/chat`，SSE），
同时走 TTS 播报与口型，链路与城市讲解完全一致。

- system prompt 会带上当前朝代、地点、诗词全文、写作地与「一说」措辞，人格是"这一朝的讲解员"；
- 对话**只走大模型**（不做本地 Mock 兜底）：`.env` 里配置 `OPENAI_API_KEY`（可指向兼容网关）即可，
  未配置时接口返回 `409 LLM_KEY_MISSING` 并给出配置提示；
- 会话记录沿用 `ChatSession/Message` 表，`city_slug` 形如 `dynasty:tang:place:changan`，与城市会话互不混淆。

## 四、数据与扩展

- 数据在 `backend/app/data/`：
  `dynasty_tang.py` / `dynasty_song.py` / `dynasty_ming.py`（疆域环、地名、诗词、问答）；
  `dynasty_common.py`（`densify` 加密控制点、`place()`、`poem()` 构造）；
  `dynasties.py`（注册表、**发光字清单 `FEATURED`**、讲解员人格与 system prompt）。
- 现状：唐 17 地名 / 13 诗词 · 宋 18 / 14 · 明 15 / 12，全部公有领域古文，内嵌在 Python 模块里，不入库不迁移。
- 接口：`GET /api/dynasty/list`、`GET /api/dynasty/{key}`（返回 `outline / places / poems / featured`）、
  `POST /api/dynasty/{key}/chat`（body：`{message, place_id?, poem_id?, session_id?}`）。
- 新增朝代：照 `place()/poem()` 往新模块里加数据，在 `dynasties.py` 注册并挑几首放进 `FEATURED`，
  前端不用改（列表、光点、光字、卡片都按数据结构渲染）。
- 校验：`python tools/browser_check_dynasty.py` 覆盖进入/悬停/点卡/光字/对话/诗词/返回现代/三朝切换与零控制台错误。
