穿越模式覆盖**秦 → 现代共 11 个时期**：秦、汉、三国、晋·南北朝、隋、唐、宋、元、明、清、现代。
它和行程规划是**两条互不干扰的路线**：穿越模式只看历史，不做流程编辑与优化；
退出后现代底图与全部图层原样恢复。

## 一、进入与退出

1. 打开「☰ 导航 → 穿越」，在下拉里选时期（秦 → 现代，按时间顺序）；
2. 点「开始穿越」：沙盘浮雕底图**整体重建为该朝的示意疆域**（`outline` 闭合环），
   现代城市光点、地级市标注、省界省名、3D 地标全部收起；
3. 顶部出现**朝代状态条**（时期 · 都城 · 年代 · 地名/诗词数量），点 **◀ / ▶** 可以沿时间线前后切换时期，
   随时点「返回现代」恢复全部现代图层。

从抽屉进「我的攻略 / 流程编辑 / 路线规划 / 抄作业」时会**自动先返回现代**，避免拿历史疆域去排现代点位。

## 二、地图上能看到什么

- **历史地名**（光点 + **常驻名牌**）：名牌挂在地名光点下方，**像现代地图一样分级常显**——
  近景写「古名 + 今名」（长安 / 西安），中远景自动收起今名只留古名、字号收小，让更多地名进得来；
  都城优先占位，**上一帧已显示的名字粘性保留**（相机不动时可见集合完全一致，不会忽隐忽现），
  次级地名（更小更淡的 tier-3 名牌）随后填空。全国视野下每个时期可见 **11–20 个地名**。
  光点与名牌按类型分色分级：**都城**金、州府纸白、关隘/港口青、寺观/名胜淡紫，次级地名统一淡灰。
  点光点或名牌都能打开卡片，看类型、简介、讲解词与内置问答。
- **驿道光带**：把这一期的城、关、港按**最近邻**连成一张路网（每期 29–38 段细光带，
  夜色里更亮一点），既填满空旷的沙盘，也让人一眼看出城与城之间的走向。
- **诗词光点**（青色）：诗词写作地；同一地点多首诗绕成一个小环，点开是诗词卡——全文、背景、
  写作地今名，以及**「一说」存疑标注**（例：《静夜思》写作地一说扬州旅舍、一说安陆）。
- **光韵诗字（每个时期全部诗词都发光）**：该时期的 **10–14 首诗词全部**在写作地上浮起两列竖排的
  「光字」——每个汉字都是 canvas 画出的带光晕字形、按列合成贴图，**加色混合叠在沙盘上，
  没有纸面或碑体背景**；笔画接近暖白、外圈是金色光晕，整列朝向相机并轻微浮动呼吸。
  字串后有一层很淡的暗晕（白天保证可读）、一圈柔光与一道从地面升起的光柱；夜里整体更亮，
  悬停时整串字放亮放大。其中 **6 首代表诗词**（`FEATURED`）另挂一枚青色题名签《题名》，
  **和地名的青/金配色区分开**；点光字、题名签或光点都能打开对应的诗词卡。
  视野拉得很远时只保留代表诗词、靠近后全部诗词一起发光（LOD）。
- **昼夜随行**：底图重建后日照 uniforms 照常工作——把时间滑到夜里，该朝疆域一样会入夜，
  历史地名与诗词标记按各自所在地的昼夜独立亮灭。
- 抽屉里还有**「本朝诗词」列表**，点一首即飞到该诗的写作地并弹卡。

## 三、与数字人讨论（走大模型）

卡片底部输入问题即可：回答走的就是**数字人原本那套对话链路**（同一个 `services/llm.stream_reply`
与 `voice.askDynasty` → SSE → TTS → 口型），不同之处只有提示词——服务端把「哪一朝、都城、
当前是地点还是诗词（含全文与写作地）」写进 system prompt，其余不做特殊处理。

- 提示词模板在 `backend/app/data/dynasties.py` 的 `PERSONA_TEMPLATE`，只做「角色 + 背景 + 当前话题」三件事，
  要改口吻改这一段即可；
- 没有 `OPENAI_API_KEY` 时与城市讲解一样退回本地知识库；配置后即走大模型（可指向兼容网关）；
- 会话记录沿用 `ChatSession/Message` 表，`city_slug` 形如 `dynasty:tang:place:changan`，与城市会话互不混淆。

## 四、数据与扩展

- 数据在 `backend/app/data/`：每个时期一个模块
  （`dynasty_qin.py` / `dynasty_han.py` / `dynasty_sanguo.py` / `dynasty_jin.py` / `dynasty_sui.py` /
  `dynasty_tang.py` / `dynasty_song.py` / `dynasty_yuan.py` / `dynasty_ming.py` / `dynasty_qing.py` /
  `dynasty_modern.py`），每个模块都是「控制点 → `densify()` 加密成闭合疆域环 + 地名表 + 诗词表」；
  `dynasty_common.py`（`densify` 加密控制点、`place()`、`poem()` 构造）；
  `dynasties.py`（注册表、**发光字清单 `FEATURED`**、讲解员人格与 system prompt）。
- 数据全部内嵌在 Python 模块里，不入库、不做迁移；新增时期只要加一个模块并在 `dynasties.py` 注册即可。
- 接口：`GET /api/dynasty/list`、`GET /api/dynasty/{key}`（返回 `outline / places / poems / featured`）、
  `POST /api/dynasty/{key}/chat`（body：`{message, place_id?, poem_id?, session_id?}`）。
- 新增时期：照 `place()/poem()` 往新模块里加数据，在 `dynasties.py` 注册并挑几首放进 `FEATURED`，
  前端不用改（列表、光点、光字、卡片都按数据结构渲染）。
- 校验：`python tools/browser_check_dynasty.py` 覆盖进入/悬停/点卡/光字/对话/诗词/返回现代、
  11 个时期逐个切换、地名标签可见性、◀▶ 时间线切换、缓存后的切换耗时与零控制台错误。

## 五、流畅度与懒加载

- **朝代详情按需加载**：只有点「开始穿越」才请求 `GET /api/dynasty/{key}`，并在内存里缓存
  （`state.payloads`），来回切换同一时期不再重复请求；实测缓存后切换约 **141 ms**。
- **光字延后一帧生成**：切时期时先把疆域底图这一帧画出来，再建光字（`setTimeout(..., 60)`），
  切换手感更顺；字形贴图按字缓存并设上限，超过上限自动淘汰最早的几张。
- **地名标签节流刷新**：标签投影与防重叠计算每 120 ms 一次，不占每帧预算；省份、地级市、
  3D 地标在穿越期间整体隐藏，绘制对象更少。
- **11 个时期也不会同时驻留**：同一时刻只有当前时期的标记与光字在场景里，退出即释放几何与材质。

无头软件渲染下的实测（最差情况）：现代沙盘 34 fps / 穿越模式（唐：27 处地名、18 个常驻名牌、
13 首诗全部发光、33 段驿道）35 fps，**相对帧率约 103%**——光字用「一列一面片 + 贴图按列缓存」，
驿道只是一条线对象，名牌是节流 120ms 的 DOM，密度上去了但每帧预算没变；
在带显卡的普通环境下两者都会高得多，自适应画质照常工作。
